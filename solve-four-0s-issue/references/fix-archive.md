# 「4个0」问题修复归档

本文件由 `solve-four-0s-issue` 技能在问题修复完成后追加，只记录**问题类别**与**解决方案**，作为后续同类问题的修复参考（技能自进化）。

## 写入规则

1. 类别用扫描结果里的规则名，例如 `JS.BASE.EQEQEQ`、`NO_EFFECT`、`MASS_ASSIGNMENT`。
2. 严格脱敏：不得出现项目名/仓库名、文件路径或文件名、代码片段、行号、漏洞 ID、任务或执行链接、分支名、提交者姓名工号，以及任何凭据。
3. 解决方案写成可复用的通用手法（改什么、怎么改、注意什么），不要绑定某一次具体改动。
4. 同一类别已存在时不新增条目，合并进已有条目并更新「修复次数」与「最近更新」。

## 条目格式

```md
### <工具> / <问题类别>
- 解决方案：<通用修复手法，1-3 句>
- 修复次数：<整数>
- 最近更新：<YYYY-MM-DD>
```

## Klocwork

### Klocwork / JS.BASE.EQEQEQ
- 解决方案：把「不等于 null」这类松散比较改为严格比较，并把 null 与 undefined 的判空显式展开为两个严格比较条件，保持原判空语义不变；同一处过滤链上的兄弟写法要一并改，避免同类告警再次出现。
- 复现手法：本地 ESLint 的同名规则（eqeqeq）可直接复现该告警，改完即可本地自检，无需等平台重扫。
- 修复次数：1
- 最近更新：2026-09-22

### Klocwork / JS.BASE.REQUIRE.ATOMIC.UPDATES
- 解决方案：该规则来源于「await 之后基于过期状态赋值」的启发式检查，判定点是「写操作之前曾读过该变量」。异步等待之后、写回该状态之前先重新读取一次当前状态，仅在仍处于预期状态时才赋值（等价于比较后再写），即可消除告警且不改变行为。
- 复现手法：该规则是 ESLint require-atomic-updates 的移植（告警文案逐字一致），可用本地 ESLint 以该规则直接复现与自检；同函数内可能还有其它同类赋值点，修完应重新跑一遍确认不再触发。
- 修复次数：1
- 最近更新：2026-09-22

## Coverity

### Coverity / NO_EFFECT
- 解决方案：去掉仅为丢弃返回值而加的 void 运算符，直接调用该异步方法；调用方不关心返回值时无需额外包装，也不要为了消除告警加无意义的判断。
- 修复次数：1
- 最近更新：2026-09-22

### Coverity / MASS_ASSIGNMENT
- 解决方案：该规则针对请求参数自动绑定到对象上的敏感名称字段（名称形态类似 xxxKey/xxxRole/xxxFlag，存在越权风险）。处理方式为在进入业务逻辑前对该字段做白名单或取值范围过滤，非允许值直接返回业务错误；若确认字段取值本就是受控枚举且无越权影响，可选择在平台上做误报备案，而不是改名或加无意义判断绕过。
- 修复次数：1
- 最近更新：2026-09-22

### Coverity / FB.RV_ABSOLUTE_VALUE_OF_RANDOM_INT
- 解决方案：不要对随机数取绝对值（最小负数的绝对值仍为负）。改为用取模归一化的非负函数（floorMod 之类的归一到 [0, 区间长度) 后再平移），或直接使用带上下界的随机取值接口。
- 修复次数：1
- 最近更新：2026-09-22
